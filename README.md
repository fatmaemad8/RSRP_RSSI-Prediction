# RSRP & RSSI Signal Strength Prediction

A machine learning and exploratory data analysis (EDA) project designed to predict LTE cellular signal quality metrics—specifically **RSRP** (Reference Signal Received Power) and **RSSI** (Received Signal Strength Indicator)—using flight trajectory, spatial coordinates, and network telemetry data.

## Project Overview

This project analyzes wireless network telemetry collected during an unmanned aerial survey and trains **Random Forest Regression** models to predict `rsrp` and `rssi` values on unseen data. In addition to predictive modeling, the repository provides statistical and visual analyses examining how altitude, spatial coordinates, flight phases, and cell parameters influence cellular signal behavior.

## Dataset Description (`ml.csv`)

The dataset comprises LTE network telemetry and spatial measurements structured as follows:

* **Spatial and Temporal Features:** `timestamp`, `rel_time`, `longitude`, `latitude`, `altitude`
* **Cell and Network Parameters:** `pci` (Physical Cell ID), `ci` (Cell ID), `is_connected`, `tac` (Tracking Area Code), `earfcn`, `ta` (Timing Advance)
* **Signal Metrics:**
  * `rsrp` *(Target 1)*: Reference Signal Received Power ($\text{dBm}$)
  * `rssi` *(Target 2)*: Received Signal Strength Indicator ($\text{dBm}$)
  * `rsrq`: Reference Signal Received Quality ($\text{dB}$)
  * `asu`: Arbitrary Strength Unit

## Important Notes Before Execution

1. **Dataset File Path (`ml.csv`):**
   * The notebook clones the repository into a subdirectory named `RSRP_RSSI-Prediction/` and reads `RSRP_RSSI-Prediction/ml.csv`.
   * When running locally inside the repository root directory, ensure the file path points to `"ml.csv"` (or maintain the expected directory hierarchy) to avoid `FileNotFoundError`.

2. **Branch Configuration in Google Colab:**
   * The initialization cell explicitly clones the `HODA-ELTOHAMI` branch (`git clone -b HODA-ELTOHAMI ...`). Update the `branch_name` variable if evaluating a different branch.

3. **Handling `"Unavailable"` String Entries:**
   * Raw columns (`ci`, `tac`, `ta`) contain the literal string `"Unavailable"`. These entries must be converted to `np.nan` prior to numerical casting or model training.

4. **Removal of High-Missingness Features:**
   * Columns `ci` and `tac` contain approximately $88.73\%$ missing values and are excluded during preprocessing.
   * Column `ta` is cast to a numeric type (`errors="coerce"`) and imputed using its median value.

5. **Prevention of Data Leakage (`asu` Exclusion):**
   * The `asu` feature exhibits a perfect linear correlation ($r = 1.00$) with `rsrp`, as Arbitrary Strength Unit values are directly derived from RSRP in LTE standards. Consequently, `asu` is excluded from the feature matrix $X$ alongside `rsrp` and `rssi` to prevent target leakage.

6. **Sequential Execution Order:**
   * Cells must be executed strictly from top to bottom. Later exploratory cells append categorical helper columns (`altitude_5m`, `flight_phase`) to `df`; re-running modeling cells afterward without re-initializing `df_clean` may result in feature schema mismatches.

## Methodology and Workflow

1. **Data Cleaning and Missing-Value Assessment:** Converted `"Unavailable"` entries to `NaN`, quantified missingness across all features, dropped columns exceeding $80\%$ missing data (`ci`, `tac`), and applied median imputation to `ta`.
2. **Train-Test Partitioning:** Partitioned the dataset into training ($80\%$) and testing ($20\%$) subsets (`random_state=42`) while preserving aligned row indices across both target variables.
3. **Model Training and Evaluation:** Trained two independent `RandomForestRegressor` models (`n_estimators=50`, `random_state=42`) for `rsrp` and `rssi`, evaluating predictive performance using **Mean Absolute Error (MAE)** and the **Coefficient of Determination ($R^2$)**.
4. **Exploratory Data Analysis:** Investigated signal distributions, feature correlations, altitude stratification in $5\text{-m}$ intervals, spatial flight trajectories, and time-segmented flight phases.

## Key Exploratory Findings

* **RSRP and RSSI Correlation:** The two signal metrics demonstrate a strong positive linear relationship ($r \approx 0.95$).
* **Altitude Dependence:** Signal strength improves substantially as altitude increases up to approximately $35\text{--}40\text{ m}$, with median RSRP rising from roughly $-106\text{ dBm}$ at low altitudes to $-82\text{ dBm}$ above $30\text{ m}$.
* **Flight Phase Segmentation:** Segmenting the mission by `rel_time` identifies three distinct flight phases in which median RSRP closely tracks variations in drone altitude.
* **RSRQ Lower Measurement Floor:** RSRQ observations cluster noticeably at $-20\text{ dB}$, suggesting a lower measurement floor in the logging instrumentation.
